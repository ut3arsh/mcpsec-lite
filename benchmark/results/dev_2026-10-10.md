## Where the Defense Fails and Why (Honest Red-Team Limitations)

1. **Cross-Session Replay (ATTACK-13):** The firewall isolates sessions individually. If untrusted state persists outside proxy memory (e.g. in workspace files) and is invoked by a clean session, taint is not carried over.

2. **Data Laundering (ATTACK-14):** Taint sources match declared glob patterns (`**/.env*`, `**/secrets/**`). Writing sensitive data into unmonitored filenames (`cache.tmp`) bypasses source tagging.

3. **Unless-Exempt Observable Sinks (ATTACK-15):** The `unless: { domain_allowlist: ['api.github.com'] }` exemption allows legitimate multi-step API queries. An attacker controlling an endpoint on an allowlisted domain can receive exfiltrated data.

4. **Parameter Smuggling on Read-Only Tools (ATTACK-16):** Tools tagged solely with `network_read` (such as `github.get_issue`) do not trigger flow rules denying `egress`, enabling data exfiltration via caller-controlled query parameters.

5. **Approval Fatigue (ATTACK-17):** Human-in-the-loop elevation relies on operator diligence. Auto-approval daemons or fatigued operators will approve malicious operations.

6. **Allowed-Channel Leakage (ATTACK-19):** Commenting confidential data onto internal repositories is permitted by coarse write policies.

7. **Upstream Redirects & TOCTOU (ATTACK-20, ATTACK-21):** Known gaps documented in `test_known_gaps.py` (upstream following HTTP 302 redirects and filesystem symlink swap race conditions).
